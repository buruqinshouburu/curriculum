# 空课程编号补全

这是独立的数据修复操作，不是部署启动时自动执行的脚本。MySQL 8.0+。

## 范围和规则

- 仅更新 t_csys_course 中 sysflag=0、type=1/2/3/4、code 为 NULL/空字符串/纯空格的记录。不覆盖已有编号，不处理删除数据。
- 此次按全部空编号数据处理，不限 template_type=1，包含培养方案内的调用副本；每条记录独立续号，不合并历史记录、不更改关联关系。
- 与 getCourseCode_new 对齐：版本末两位-培训层次代码-单位代码-至少四位流水号。
- 层次：1=JG，2=DB，3=SG，4=JD，5=JS，6=DS，7=YL，8=JY；其他非空值按源码保留原值。
- 单位代码严格按 CollegeEnum，单位名存在但未收录时为00。单位名称从 sys_dept 按 college_id 获取。
- 同前缀从现有未删除记录的最大流水号后续编，以 id 升序分配。10000及以上不截断。不能解析的已有编号前缀整组跳过，超过 Java Integer 范围跳过。
- 版本不足两位、培训层次为空、单位未查到或名称为空，跳过并列出。不猜测业务字段。

## 操作

1. 备份数据库，暂停所有课程新增、修改、导入和相关后台任务，直到最后提交或回滚。脚本不解决并发生成编号的竞争。
2. 打开数据库 SQL 编辑器，确认 SELECT DATABASE() 指向业务库。如 sys_dept 在其他库，先给预览脚本里的 sys_dept 加真实库名前缀。
3. 执行 `20261116_preview_missing_course_codes.sql`。这一步只生成临时表和查询，未修改业务表。
4. 检查跳过的数据、拟更新列表、missing_count/planned_count，以及最后两个冲突查询。最后两项必须无记录。导出拟更新列表留档。
5. 保持同一个连接（不要关闭窗口或重连），执行 `20261116_update_missing_course_codes.sql`，核对 updated_count 等于 planned_count，检查编号。
6. 确认无误后单独执行 `COMMIT;`，不正确则执行 `ROLLBACK;`。更新脚本故意不自动提交。更新之后不能在未提交时重新跑预览。
7. 提交后再刷新页面验收、恢复服务。再次完整执行预览不会重编已补好编号的记录。

只运行 UPDATE 不能省略预览，因为 UPDATE 依赖该连接中的临时表。
若任一步报错，先 ROLLBACK，再排查，不要忽略报错继续 COMMIT。
