# 培养方案 SQL 视图更新（2026-11-17：细化专业方向）

## 执行方法

适用 MySQL 8.0+。先备份旧视图定义，确认当前连接业务数据库。
先执行累计更新包内 `20261110_course_major_selection.sql`、`20261112_course_invocation_directions.sql` 中尚未成功执行的脚本，确保课程表存在 `invocation_sub_major_ids` 字段。

依次执行：
1. `01-course-time-credit.sql`：新建共享时长/学分视图。
2. `02-hours-credits.sql`：替换 `v_csys_scheme_hours_credits`。
3. `03-scheme-import.sql`：替换 `v_csys_training_scheme_import`。
4. `04-check-and-query.sql`：只读核对，不修改业务记录。

如果已执行 20261117-r3 累计包中的旧版视图，只需重新执行本次修改的 `02-hours-credits.sql` 和 `03-scheme-import.sql`，再执行 `04-check-and-query.sql` 核对；`01-course-time-credit.sql` 无变化，不需要重复执行。

需要创建视图及读取基础表的权限；视图采用 SQL SECURITY INVOKER，查询账号也需要基础表读取权限。
若 `sys_dict_data`、`sys_dept` 位于另一数据库，请在 SQL 中这两个表名前加实际库名。
以上三个视图脚本可以重复执行，不增加、删除或回写课程业务数据。视图提供全量数据，不代替应用权限过滤。

## hours_credits

- 按“培养方案 + 单个专业方向”分组，每个方向独立展示模块、小计及合计，不再将所有专业方向拼成一长串。
- 优先使用方案专业方向关系；无关系时兼容旧的单专业方向字段。课程归属参照后台调用范围：多方向、旧单方向、公共课程及同源专属副本覆盖。
- 同一关系重复记录去重；独立的历史课程记录不合并。公共课程会计入每个适用方向，因此不要把多个方向的合计再次相加。
- 保留原来的课程体系、实践训练体系统计和军士模板口径；首页“实践项目不参与排课统计”不套用到此 Word 表格视图。
- 新增专业方向ID、学时单位、必修周数、选修周数、小计周数、周数单位。周不换算为学时，也不与学时混加。
- 本次追加“专业方向编号”，优先显示方向 code，缺失时显示方向 ID；已有分方向分组口径不变。
- 模块名称继续使用源码内已知映射，未知模块显示原 ID；其他字典没有匹配项也保留原值。

## scheme_import

- 每行细化为“培养方案 + 单个专业方向 + 课程”，专业号、专业名称分别展示单个方向的编号与名称，不再拼接多方向。追加培养方案ID、专业方向ID、专业方向、课程ID四列，便于筛选与关联。
- 课程方向筛选与 hours_credits 一致：多方向明确归属优先，兼容旧单方向、公共课程、同源专属副本；独立历史记录保留。无方向方案仍保留数据，显示“未设置专业方向”。
- 专业总学分要求只匹配当前方向或其专业类的大纲要求，不再汇入其他方向的要求。公共课程仍在每个适用方向中展示，跨方向汇总会重复计入，不应直接相加。
- 原视图已经要求培养方案、课程、排课记录的 `sysflag=0`，不会包含 `sysflag=2`。新版保留此规则，并提供专项核对查询。关系表没有 sysflag 字段，不对关系表虚构过滤条件。
- `type=2/4` 的“总学时”列读取 `time_Week`；为兼容旧列名未重命名，该列对这两类实际表示时长，须结合新增的“单位”列查看。
- 保留“单位”“实际学时”“周数”，本次追加标识列后共 44 列，不再是旧 XLS 模板的 37 列。依赖列位置的导出/导入调用方需要使用明确列名，不要直接将全部列当作旧模板上传。
- 单位编码 1（空值按后台默认）= 周，2 = 学时。周按 1 周 1 学分，学时按 16 学时 1 学分。
- 学分沿用后台取整规则：小数不足 0.5 向下取整，等于 0.5 保留半学分，大于 0.5 向上取整；不是简单保留两位小数。
- 有学年安排明细时逐条按单位换算后合计，再统一取整；无明细时用课程 time_Week 和 unit 换算。普通课程仍用原学分。
- 混合单位标注“混合（学时/周）”，只看“实际学时”“周数”的分项，不要汇总该行的原始时长。无效单位或负时长不产生有效学分，应使用核对脚本查出并修复源数据；汇总视图对空值按 0 汇总。
- 各学期学时仍取已有排课学时；按课程方向范围分别统计，排课表没有独立方向列，不虚构该字段。共用同一课程记录的方向沿用相同排课；周制数据不会伪造学期学时。
