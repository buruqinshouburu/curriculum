# 贯穿四年统一到第八学期

## 适用范围

所有未删除的普通课程、实践训练课目、实验课程、实践项目（type=1/2/3/4）。课程关联学年安排明细 `t_csys_course_ref_schedule.semester_schedule=6` 是识别依据，不再限于实践训练课目。

本次代码负责新调用、修改保存及重新生成排课；**已保存的排课不会因为部署代码自动变化，需执行本脚本处理存量**。

## 执行步骤

1. 备份业务数据库并暂停课程和排课写入。先部署本次前后台更新，维护窗口内完成以下操作。
2. 在业务数据库运行 `20261116_preview_four_year_final_term.sql`。核对每个培养方案、课程、原学期、新学期及学时。最后一份结果为仅主表有标记的待人工核对记录，不会自动迁移。
3. 保持同一数据库连接，运行 `20261116_update_four_year_final_term.sql`。临时表不存在则不能运行，不要跳过预览。
4. 校验查询应返回零行。确认学时后手动执行 `COMMIT;`；有问题执行 `ROLLBACK;`。关闭连接、切换窗口或客户端自动提交可能影响事务，请先确认工具设置。
5. 重新运行预览，迁移范围应为零。刷新首页、配置教学执行计划，核对第八学期及专业方向。

## 数据规则

- 按培养方案ID和课程ID处理，不把不同课程副本、不同专业方向调用记录合并。
- 同一组保留最小ID的一条记录，学期改为8，物理删除其余排课行；覆盖现有手动排课。
- 原排课的讲授、实践、理论分配学时分别求和，仅累计一次；选中状态取最大值。原整门课程总学时、学分不相加，沿用保留行。
- 不修改课程学年安排明细、时间安排、单位或源库字段。不创建原本没有配置的排课，不处理已删除课程、方案或排课。
- 历史展开时若已丢失明细中的6标记，本脚本不会凭“有四年数据”猜测。请人工核实后在课程编辑中重新选择贯穿四年并保存。
- 原排课如已错误复制了多份学时，脚本无法区分实际分配与误复制。预览必须核对合计，发现异常先不要提交。
- 提交前可事务回滚；提交后若需恢复，应从数据库备份恢复受影响排课记录。
