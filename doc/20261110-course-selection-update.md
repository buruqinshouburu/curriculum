# 课程专业多选与安排同步更新

## 部署顺序

1. 备份数据库，执行 `sql/20261110_course_major_selection.sql`。脚本只新增 `t_csys_course.major_ids`、`sub_major_ids` 两个可空字段，可重复执行，不改已有课程数据。
2. 更新并构建 `csys-service-api`、`csys-service`。
3. 更新前端源码并打包。此次不调整 Mock 环境开关。

不能只更新前端或只执行 SQL；前后端需配套更新。

## 字段与范围

- 课程新增/修改接口沿用 `POST/PUT /csys/curriculum/course`。
- 新增 `majorIds: number[]`（专业类）、`subMajorIds: number[]`（专业方向）。数据库使用逗号分隔字符串，接口始终为数组。
- 数组为 `null` 表示历史记录尚未维护多选字段；`[]` 表示明确清空，不再回填旧单值。
- 学科基础课程的学科门类、专业类、专业方向可不选，后两项可多选。
- 专业课程且修读要求为任选时，专业类、专业方向可多选，仍按原规则必填。
- 多选源课程提交的 `majorId/subMajorId` 为 `null`；已调用课程保留原单值的树节点归属，多选范围另存数组，避免修改后从专业方向节点消失。
- 删除某专业类时移除其下已选方向；未选专业类时，方向不限制专业类。
- 培养方案 Word 中，学科基础课程名称后附全部已选专业方向名称，不修改课程原名称。

## 调用与覆盖规则

- 军士职业教育的任职基础、任职岗位：同一源课程在同一子模块、同一专业方向只调用一次，不同方向可以分别调用。其余模块去重规则不变。
- 保存源库课程（type=1/3）时，明确提交的 `courseScheduleList` 覆盖全部引用副本的课程安排及方案排课，包括方案自定义的学年、学期、讲授学时、实践学时。
- 保留被调用课程的模块、子模块与专业方向归属。不把实践训练课目（type=2）、实践项目（type=4）的周次纳入此次同步。
- 未提交课程安排时不触发覆盖；提交空数组表示清空。前端正常新增/编辑仍要求至少一条完整安排。
- 同步处于课程保存事务内，任何一步失败则回滚。

## 验收建议

1. 学科基础课程不选专业保存、多选保存、重新打开回显，再清空保存。
2. 专业任选课选择多个专业类及方向，移除一个专业类，确认仅移除其下方向。
3. 同一军士任职类课程分别调用到两个方向，再次调用到同方向应阻止。
4. 在两个培养方案修改同一源课程的排课，再从源库修改安排及学时，确认两边被覆盖且模块归属不变；无关课程不变。
5. 导出含多方向学科基础课程的培养方案，确认全部方向名称都出现在课程名后。

SQL 未自动在业务数据库执行；应先在测试环境完成上述验收，再更新内网。
