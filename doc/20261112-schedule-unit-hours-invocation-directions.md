# 2026-11-12 排课展示、知识单元学时及调用方向调整

## 本次规则

1. 首页排课隐藏统计不完整、学时待完善及对应提示。仍按实际可统计学时累计，不把缺失值伪造成已完整统计；超限预警保留。课程较多时由页面整体纵向滚动。
2. 知识目标教学实现设计中，学时属于知识单元。学时列与知识单元列按同一源单元标识合并，不按知识点累加。历史同单元设计学时不一致时，按源知识点顺序取首个非空值，0 为有效值；编辑后同单元统一。目标、内容、教法等仍按选中知识点修改。Word 导出与页面一致，导入忽略仅带合并学时的空设计占位行。
3. 构建课程体系中，军士职业教育的任职基础、任职岗位调用课程支持专业方向多选。旧记录保持独立，不合并，不删除。

## 调用方向字段与数据库

更新前执行 `sql/20261112_course_invocation_directions.sql`。脚本可重复执行，仅新增可空列 `t_csys_course.invocation_sub_major_ids`，不回填或改写旧数据。上一版 `20261110_course_major_selection.sql` 仍是源课程多专业字段的前置条件，已成功执行不用重复执行。

- 课程详情及保存新增 `invocationSubMajorIds` 数字数组。与源课程适用范围 `subMajorIds` 分开。
- NULL/未提供：兼容旧 `subMajorId`；旧单值仍为单方向，旧空值仍为专业类全部方向（含未来新增）。更新时省略该字段不清除已保存数组。
- 非空数组：以数组作为当前调用方向，旧单值不参与匹配。
- 不接受空数组，避免误扩成全部方向；方向必须属于培养方案对应专业及所选方向。
- 新增选择不能与同来源、同模块、同专业范围的其他明确方向记录重叠。历史已有重叠不合并，不因未改变的历史范围阻止其他字段编辑。
- 方案列表、排课、导出及调用去重同步识别多方向。专业类通用记录仍作为没有方向专属记录时的回退。

## 知识设计保存接口

`POST /csys/teachingPlan/targetDesign/batchSave`

```json
{
  "planId": 60,
  "rows": [
    {
      "id": 101,
      "planId": 60,
      "designTypeCode": "1",
      "hours": 8,
      "knowledgePoints": [
        { "knowledgeUnitId": 11, "knowledgePointId": 111 }
      ]
    }
  ]
}
```

rows 使用现有 targetDesign 实体完整字段，上例仅示意关键字段。有 id 修改，无 id 新增；返回与 rows 顺序对应的记录 ID 数组。仅更新提交的记录，不删除整个 TAB。后台验证计划权限、记录归属、目标和方案范围，并在同一事务中提交，任一失败整体回滚。能力、素质目标保持原接口。
