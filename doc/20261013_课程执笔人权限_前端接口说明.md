# 课程执笔人权限：前端接口说明

更新时间：2026-10-13。已按最新要求收窄为总库课程、源课程知识体系和课程教学计划三类。

## 一、前端需要调整的内容

1. 人员统一称“执笔人”，多选系统用户，不区分负责人、团队成员。
2. 仅总库课程基本信息修改/删除、源课程知识体系保存/导入、课程教学计划写操作受课程权限控制；现有执笔人或具有 `cur` 角色权限符的用户可操作，执笔人名单为空时创建人也可操作。总库课程及教学计划页面使用总库课程 ID 查询 `canOperate`。
3. 人员配置使用独立接口，按钮由 `canConfigureAuthors` 控制，不再通过普通课程修改提交名单变化。
4. 具有 `cur` 角色权限符的用户可操作所有课程的上述三类受控内容及配置执笔人，无需列入名单。没有 `cur` 角色的创建人：名单为空时可编辑，名单有人员且自己不在其中时仅可配置名单。系统管理员未命中编辑规则时仅可配置名单；培养方案调用课程操作不受本次限制。创建人配置名单不限制次数。
5. 调用课程没有知识体系编辑入口，只查询共享体系；后端也拒绝向调用课程提交知识体系保存和导入。
6. 培养方案内调用课程修改、绑定/同步毕业要求、删除引用课程等，不使用源课程执笔人权限限制，沿用既有规则。其他关联模块本轮不增加执笔人校验。
7. 对上述三类受控操作，前端遇到 HTTP 401/403 应处理失败，不能只检查业务 code 或依赖按钮隐藏。
8. 新增和导入课程不做本次新增的执笔人及关联数据校验；理论、实践计划等可选对象无需补空对象。课程新增、修改和导入的名称查重已停用，编号重复等其他原有业务校验保留。

无需执行数据库 SQL，继续沿用 `authors/author_ids/creator`。

名单为空以数据库总库课程的 `author_ids` 为 null、空字符串或只有空白字符判断。创建人使用已存 `creator` 与当前登录用户名精确匹配，不采信请求中的 creator。名单配置人员后，未列入名单的创建人立即失去内容操作权；清空名单后恢复创建人的操作权。创建人缺失时不向普通用户开放。

`cur` 从后端已认证的 `LoginUser.roles` 角色权限符集合精确匹配，用户名为 cur、角色显示名为 cur、菜单权限包含 cur 都不会放行。前端无需新增请求参数，不能自行提交角色来获得权限。角色变更后按现有登录机制刷新会话或重新登录。

## 二、请求基础

`baseUrl` 应包含实际服务或网关前缀。仓库本地配置为 `http://localhost:9219/csys`，线上按部署配置填写。

认证沿用现有登录方式，示例使用 `Authorization: Bearer <token>`。

说明中的 `courseId` 可以为总库课程或调用课程 ID。调用课程普通操作不受执笔人限制，返回的 canOperate 为 true。名单配置仍定位到总库课程，不会把调用课程创建人视作源课程创建人。

## 三、查询执笔人与当前操作能力

`GET {baseUrl}/curriculum/course/{courseId}/permission`

示例响应：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "courseId": 200,
    "permissionCourseId": 100,
    "authors": "张三,李四",
    "authorIds": "1001,1002",
    "canOperate": true,
    "canConfigureAuthors": true
  }
}
```

`msg` 为项目统一消息，示例文字仅供说明，不应作为前端判断条件。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| courseId | number | 本次传入的课程 ID |
| permissionCourseId | number | 实际维护执笔人的总库课程 ID |
| authors | string/null | 执笔人姓名集合，用于展示 |
| authorIds | string/null | 系统用户 ID 集合，英文逗号分隔，用于多选回显 |
| canOperate | boolean | 总库课程为当前用户是否为执笔人、具有 cur 角色或属于空名单课程的创建人；调用课程固定为 true，表示本次不增加执笔人限制；既有业务限制仍有效 |
| canConfigureAuthors | boolean | 是否可以维护执笔人名单 |

进入总库课程编辑、源课程知识体系或教学计划页面时，使用总库课程 ID 查询；人员配置成功后以返回值刷新能力。调用课程页面不使用源课程 canOperate 隐藏绑定、删除引用等按钮。现有课程列表/详情响应结构未增加这两个字段，前端应使用这个新增接口。

总库权限是即时计算的。教学计划必须用其 sourceCourseId 查询操作能力，不能用调用课程返回的 canOperate 为教学计划放行。显示及人员回显建议使用该接口返回的名单。

## 四、配置执笔人

`PUT {baseUrl}/curriculum/course/{courseId}/authors`

`Content-Type: application/json`

```json
{"authorIds":"1001,1002"}
```

- authorIds 必填；必须是系统用户 ID，不能传教员外库 ID、姓名或数组。
- 后端去重、校验用户存在且可用，再取系统用户姓名生成 authors；前端不提交 authors。
- 支持空字符串清空：`{"authorIds":""}`。null、缺失字段以及 `1001,,1002` 等非法格式返回 400。
- 名单的 ID 字符串及姓名字符串分别不超过数据库现有 500 字符限制。
- 现有执笔人、总库课程创建人、系统全局管理员及具有 cur 角色权限符的用户可以配置；没有另新增机构管理员识别规则。
- 配置结果会更新调用课程的复制显示字段，实际授权始终读取总库名单。

成功返回与查询接口相同的 `DataSet<CoursePermissionVo>`。以返回的 canOperate 为准：普通执笔人移除自己后可能失去权限；创建人清空名单后恢复内容操作权；cur 用户清空名单仍保留权限。

创建人不在名单里也可以配置人员；如果把自己主动加入名单，之后按执笔人身份获得内容操作权。名单清空后创建人、系统管理员或 cur 用户可以重新配置。

## 五、现有课程保存的变化

`POST /curriculum/course` 新增课程：

- 不允许携带已有 id；更新必须使用 PUT。
- 不校验当前用户是否为执笔人，不调用用户服务校验名单，不检查关联子记录；沿用现有表单提交 authors/authorIds 的方式。
- 未选执笔人允许创建，创建人可直接修改；配置人员后，只有 authorIds 中的用户及 cur 用户可修改受控内容。
- 不必提交 courseTeachingTheoryPlanVo/courseTeachingPracticePlanVo 空对象，后端沿用原流程按课程类型初始化。
- creator 由后端填为登录用户名，不能自行指定。
- 新增、修改和导入课程都允许重名；课程编号重复等其他原有业务规则保留。

`PUT /curriculum/course` 修改课程：

- 修改总库课程允许现有执笔人、cur 用户及空名单课程的创建人；修改调用课程不检查源课程执笔人。
- 总库课程不允许通过普通修改改变执笔人名单；旧表单携带未变化的 authors/authorIds 可以继续保存。调用课程的本地人员字段沿用原保存方式，不改变总库授权；creator/sourceId 等归属字段仍不能被伪造。
- 将人员选择与普通内容保存分开，名单变化先调用第四节的接口。

历史 Excel 导入仍保留原流程，不增加执笔人或课程关联数据校验，不拦截重名。仅有 authors 姓名、没有 authorIds 的历史/导入课程不会因姓名自动获得权限，应由创建人或管理员补选系统用户。

## 六、知识体系及教学计划

源课程知识体系继续使用：

- `POST /courseKnowledge/saveBatch`，请求 `{ "courseId":100, "unitList":[...] }`。
- `POST /courseKnowledge/import`，form-data 为 file、courseId、type（1追加、2覆盖）。
- `GET /courseKnowledge/list?courseId=...` 查询可以传总库或调用课程 ID，统一读取最新源课程体系。

saveBatch 的 unitList 必填，空数组表示清空；每个单元的 knowledgePoints 可以为空数组。保存仍为整表重建，旧单元/点 ID 会重新生成，成功后请重新查询列表，不能沿用保存前 ID。

后端会更新调用课程的知识单元关联，保持源课程和调用课程共用同一套最新单元/点，不为调用课程生成独立副本。教学计划引用到的旧知识记录会保留用于已存绑定，源课程当前体系仍正常重建。

向调用课程的保存/导入返回 400“该操作仅支持总库课程”；前端无需新增调用课程知识体系编辑页面。

教学计划现有接口和请求结构基本保留，主表、教员、章节、目标及引用、任务背景、训练目的、内容、目标达成设计、实践项目及明细、考核、教材、条件、组织、步骤等写入口均允许源课程执笔人、cur 用户或空名单源课程的创建人操作。教员业务表不作为授权名单。

更新/删除子记录按其已存归属判断，不能用其他课程/计划的 ID 替换归属。审核中、已通过计划不可修改/删除内容；这些业务规则对 cur 用户同样适用。生成 Word 因会回写文件，也需要 canOperate；最终回写继续检查当前登录角色或源课程执笔人资格。

## 七、失败处理

权限相关失败使用对应 HTTP 状态和统一消息体，例如：

```json
{"code":403,"msg":"您不是该课程执笔人，无权操作课程相关数据"}
```

| HTTP/code | 含义 | 前端处理 |
| --- | --- | --- |
| 401 | 未登录 | 沿用重新登录流程 |
| 403 | 未命中课程操作规则，或没有人员配置权 | 显示提示并刷新权限，禁止继续编辑 |
| 400 | 参数错误、夹带名单变化、跨课程/计划归属或向调用课程写知识体系 | 展示错误，修正请求 |
| 404 | 课程或关联记录不存在/已删除 | 退出当前编辑或刷新列表 |
| 409 | 教学计划审核中/已通过 | 切换只读状态 |
| 503 | 系统用户服务不可用，无法校验名单 | 保留用户选择，稍后重试 |

共用批量删除中只对总库课程校验上述操作规则；混入无权限总库课程则整批失败。仅删除调用课程不做执笔人校验。数据不存在等原有业务约束仍按实际接口处理，前端不能提示未经确认的“部分成功”。课程已被调用、已有引用等原有业务限制继续生效。

## 八、联调清单

- 两名执笔人登录都可以操作；名单有人员且创建人不在其中、没有 cur 角色时可以配置但不能编辑。
- cur 用户不在任何执笔人名单时可操作所有课程的受控内容、配置名单；查询返回 canOperate/canConfigureAuthors=true，清空名单后仍可操作。
- 用户名为 cur、角色权限符为 curator/CUR 或只有菜单权限 cur 的普通用户仍无上述权限；cur 用户仍遵守审核状态和记录归属约束。
- 新增课程不选人后创建人可直接编辑；无关账号不可编辑。配置其他人员后创建人立即失去内容操作权，清空名单后恢复。
- 新增课程不传理论/实践计划对象可成功；非执笔人可新增或导入同名课程，编号重复等原有校验仍生效。
- 修改名单、移除自己、清空名单后重新配置，能力字段及时刷新。
- 普通保存不夹带人员变更；新增不携带旧 ID。
- 调用课程查询到最新共享知识体系，源课程保存后刷新可见。
- 教学计划子模块及生成文件失败时正确处理 403/409。
- 批量删除混入无权限总库课程时整批失败；非执笔人可按原规则修改调用课程、绑定毕业要求和删除引用课程。
- 旧知识体系、大纲、教材、文件、版本及其他关联模块本轮不新增执笔人限制。
