# 体系态势统计接口变更说明（2026-09-18）

适用：2026-09-18 的两次统计改造及后续修复，分支 gs；基线 62ecb6f。
路径均包含服务上下文 /csys。沿用原有认证、分页及 DataSet/DataTable 包装；下文示例仅展示业务数据，不表示完整响应包装。不得将模块字典 ID 转为数字。

## 一、前端必须适配

### 1. 课程模块占比

GET `/csys/scheme/schemeType/{id}`，id 为培养方案 ID。

返回原 denominatorId/denominatorName/numeratorCount 等结构已替换为模块列表，不再返回写死的 subCourseVoList。

```json
[
  {"moduleId":"69a7f3162dc370362ef3ee6d","moduleName":"示例课程模块","courseCount":2,"totalCourseCount":8,"proportion":0.25}
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| moduleId | string/null | 有子模块按子模块，否则按课程模块；均未设置则为 null |
| moduleName | string | 图例名称；未设置显示“未设置课程模块”；字典不可用时回退 ID |
| courseCount | number | 模块下去重后的调用课程数，同一课程跨学期只计一次 |
| totalCourseCount | number | 本方案参与统计的调用课程总数 |
| proportion | number | 0—1 的占比，前端乘以 100 展示百分比；总数为零时为 0 |

范围为未删除且 checked=1 的排课。不是按 sourceId 去重，不同调用课程分别计数。模块数量动态变化，前端不得固定四类。

导出地址不变：GET `/csys/scheme/schemeType/export?schemeId=247`；POST `/csys/scheme/schemeType/multi/export`，JSON 请求体为 `[247,248]`。下载列改为课程模块/子模块、课程数、课程占比，多方案增加培养方案名称。

### 2. 讲授、实践学时

GET `/csys/scheme/schemeHours/{id}`。

```json
[{"schemeId":247,"term":1,"termName":"第一学期","sTeachHours":32,"sPracticeHours":16}]
```

示例仅列展示所需字段，原 VO 的其他字段可能仍返回默认值或 null。讲授学时使用 `sTeachHours`，不要再读取 `sTheoryHours` 或 `cTeachHours`；实践学时使用 `sPracticeHours`。按学期汇总，checked=1、sysflag=0，排课学时为空时回退课程学时；顺序按学期升序。名称以实际 termName 为准。

导出路径保持 `/csys/scheme/schemeHours/export?schemeId=247`（GET）及 `/csys/scheme/schemeHours/multi/export`（POST，ID 数组）。

### 3. 课程选用排行和明细

GET `/csys/curriculum/course/ranking`：按源课程下有效调用课程数量降序。`courseId` 现在是源课程 ID，`selectedNum` 为调用课程数，不是排课条数。字段名不变，不要求培养方案明细。

GET `/csys/curriculum/course/courseSelectStatistics`：保留原外层列表、分页和 `trainingSchemeList` 明细结构，可选 `courseName`、`types`。

```json
[{"courseId":100,"courseName":"示例课程","selectedNum":2,"trainingSchemeList":[
  {"id":1234,"term":1,"type":"69a7f3162dc370362ef3ee6d","name":"示例课程","schemeName":"示例培养方案","termName":"第一学期"}
]}]
```

明细的 `id` 是排课记录 ID。`type` **改为 string/null**，对应排课记录的模块/子模块字典 ID，不再是旧的数字课程分类；不要用 parseInt 或数字枚举解释。既有其他响应字段不删除。

明细来源为该源课程的调用课程对应的有效、已勾选排课及有效培养方案。同一调用课程跨学期会有多条明细，未排课调用课程不出现在明细，因此 `selectedNum` 不等于明细长度。

当前 `types` 参数仍为整数数组，但筛选含义已改为**源课程 course_attr**：1 必修、2 限选、3 任选；不是明细 type 的模块 ID。可传 `?types=1&types=2`；不传或空列表不筛选。明细不再按 types 二次筛选。前端须同步改筛选标签及选项，不能沿用旧五类枚举。

`/csys/course/chooseStatus/{id}` 未修改。

### 4. 学科门类专业分类

- POST `/csys/training/scheme/category`：原新增字段基础上增加 `systemType`。
- PUT `/csys/training/scheme/category`：携带 id、systemType 修改；不传或传 null 不清空旧值。
- GET `/csys/training/scheme/category/list`：返回增加 systemType，可用 `?systemType=1` 筛选，原分页不变。
- DELETE `/csys/training/scheme/category/{id}`：原逻辑删除不变，不删除共享字典。

systemType 为数值，复用系统字典 `kg_system_type`：1 优势工科专业、2 理科基础专业、3 文学法学专业、4 军事管理专业。表单增加字典下拉并回显；沿用项目已有字典查询方式，无新增字典接口或物理表。

## 二、数据口径变化，前端字段基本不变

| 接口 | 变化 |
|---|---|
| GET /csys/scheme/courseType/scale?schemeId=247 | 每学期必修 requiredCourseCount、选修 electiveCourseCount；调用课程 course_attr=1 为必修，2/3 为选修，按有效勾选排课计数。termId、termName 不变 |
| GET /csys/scheme/credit/scale?schemeId=247 | 从有效排课计算各学期学分；普通/实验课程按讲授加实践学时除以16，实践训练课目/实践项目匹配对应时间安排：周为每周1学分，学时为每16学时1学分 |
| GET /csys/homePage/courseAndSpecialized | 学院→根专业→培养方案→调用课程，按 sourceId 去重计课程数 |
| GET /csys/statistics/scheme/count | 移除 program_name IS NOT NULL 条件；沿用原字段 |
| GET /csys/curriculum/course/checkPoint?schemeId=247 | 与 knowledge/checkLogBySchemeId 共用课程范围，仍只返回原汇总，不增加明细；缺少 schemeId 返回错误 |
| GET /csys/course/viewCourseKnowledgeList/{trainingSchemeId} | 字典不存在时名称可为 null，但保留课程及知识统计；子模块为空白时回退课程模块 |

学分接口 `creditCount` 为数字，`percent` 为已经乘以100的两位小数字符串，如 `"25.00"`，不同于模块占比的 proportion；零总学分为 `"0.00"`。专业统计现按有效根专业归属学院、有效直接子专业计细分专业，不再按旧 leaf/class_id 加权。培养目标支撑度不在此次变更范围。

3. 门类新增/修改/列表回显及筛选；确认 kg_system_type 四项已在目标系统字典中存在。
4. 方案247回归 schemeHours、schemeType、courseType/scale、credit/scale，并验证单方案和多方案导出。
5. 配套更新前后端，后端完整重编译、替换产物并重启；不能仅替换 Mapper。无 DDL，不执行 SQL。
