# V4.0 统一认证帐号与课程团队调整说明

## 人员字段口径

第三方返回的 `email` 是统一认证帐号，等于系统用户的 `sys_user.user_name`；`userName` 是教员姓名，`unitName` 是单位。

| 位置 | 帐号 | 姓名 |
| --- | --- | --- |
| 课程执笔人（课程负责人） | `t_csys_course.author_ids` | `t_csys_course.authors` |
| 课程团队成员 | `t_csys_course_team_member.user_id`（字符串帐号，字段名保留） | `t_csys_course_team_member.user_name`（教员姓名） |
| 教学计划成员 | `t_csys_teaching_plan_teacher.teacher_id`（字符串帐号，字段名保留） | `t_csys_teaching_plan_teacher.teacher_name` |

课程执笔人、团队帐号串与姓名串使用英文逗号分隔、顺序对应。团队明细与计划成员同时提供 `email`，计划成员同时提供 `userName`，便于直接复用第三方人员选择结果。`userId` / `teacherId` 在这些人员接口里代表帐号，不能再传系统数字主键；纯数字帐号仍按帐号精确处理，不会查用户主键。

人员允许尚未通过单点登录注册进入系统。保存第三方帐号和姓名，不调用系统用户查询或注册接口；用户以后登录时，以可信登录上下文中的帐号匹配权限。教员姓名不参与鉴权。

## 课程执笔人保存

`PUT /curriculum/course/{courseId}/authors`

```json
{
  "authorIds": "teacher.a,teacher.b",
  "authors": "教员甲,教员乙"
}
```

两个字段顺序必须对应，重复帐号按首次出现顺序合并。传 `authorIds: ""` 清空。省略姓名时，仅复用同课程已存在的人员姓名；新增帐号必须提供第三方姓名。既有执笔人配置授权、管理员/cur 特殊规则保留。

## 课程团队成员

`PUT /curriculum/course/{courseId}/teamMembers` 全量保存可见名单；`POST` 同路径追加。

推荐直接传第三方人员数组：

```json
{
  "members": [
    {"email": "teacher.a", "userName": "教员甲", "unitName": "单位甲"},
    {"email": "teacher.b", "userName": "教员乙", "unitName": "单位乙"}
  ]
}
```

也兼容对应课程执笔人的帐号串/姓名串：

```json
{
  "teamMemberIds": "teacher.a,teacher.b",
  "teamMemberNames": "教员甲,教员乙"
}
```

原 `userIds` 接受帐号数组或帐号串，并配套 `teamMemberNames`。`members: []` 或空帐号串清空可见名单。

- `GET /curriculum/course/{courseId}/teamMembers` 查询明细。
- `DELETE /curriculum/course/{courseId}/teamMembers?userIds=teacher.a,teacher.b` 按帐号移除。
- `GET /curriculum/course/{courseId}/permission` 返回帐号串、姓名串、明细和操作能力。
- 同一课程同一帐号只有一条团队记录，删除后重新加入复用原行。
- 负责人和团队身份独立。显式选入课程团队的负责人可保留团队行，查询显示时隐藏；全量保存可见名单不会删除隐藏的负责人团队身份。改变负责人不会删除团队数据。
- 调用课程的团队仍按既有总库解析规则读写。

## 课程权限

课程内容的人员授权按登录帐号精确匹配：课程执笔人帐号，或有效团队成员帐号。既有 cur 特殊授权保留；姓名相同、数字 ID 相同或帐号部分匹配都不授予权限。

仅有创建人身份时：执笔人和团队均为空，可以编辑并初始化团队；配置任一人员后，不再因创建人身份获得内容或团队维护权限。创建人若同时是负责人/团队成员，其人员身份仍正常授予权限。

材料绑定/解除、独立理论/实践教学计划、课程章节、课程教材与课程目标配置补上课程鉴权，更新子记录时校验原始归属，不能换课程。上传材料先鉴权，再调用文件服务；最终绑定再在事务内锁定课程校验。

按用户确认，旧知识单元、旧知识点及其旧关联接口不做本次改造。

## 教学计划人员

原单条 `POST /teachingPlan/teacher` 与 `PUT` 继续使用，支持直接传第三方字段：

```json
{
  "planId": 101,
  "email": "teacher.a",
  "userName": "教员甲",
  "professionalTitle": "讲师",
  "duty": "主讲",
  "lectureContent": "课程第一章"
}
```

`teacherId/teacherName` 分别是 `email/userName` 的兼容字段，调用时选一组即可。修改记录需带 `id`，新增禁止携带已有记录 ID。单位目前不存入教学计划成员表，保持原字段范围。

`POST /teachingPlan/teacher/batch` 支持批量新增或编辑：

```json
{
  "planId": 101,
  "teachers": [
    {"email": "teacher.a", "userName": "教员甲", "professionalTitle": "讲师", "duty": "主讲", "lectureContent": "第一章"},
    {"email": "teacher.b", "userName": "教员乙", "professionalTitle": "教授", "duty": "指导", "lectureContent": "第二章"}
  ]
}
```

批量修改指定记录时带成员 `id`；不带 ID 且同帐号已存在时，更新该计划的已有成员。每个成员只属于指定计划，不能使用其他计划的记录 ID。

- 候选人：`GET /teachingPlan/teacher/candidates?planId=101`，负责人和团队按帐号去重，并返回已选择标记、计划成员记录 ID。
- 新建计划时保存负责人快照为计划成员；无负责人时正常创建。以后改变负责人不覆盖已有计划人员，删除最后一个成员后不会再自动回退当前负责人。
- 新增或更换计划人员时，将帐号与姓名同步加入课程团队，已是负责人或团队成员则跳过重复同步。
- 仅编辑姓名、职称、职责、主讲内容等资料时，不重新同步；课程团队曾移除的成员不会因资料保存重新入队。
- 单条入口、批量入口均按帐号去重。同一帐号在不同计划的职称、职责、主讲内容分别保存。
- 移除计划成员只改计划关联；移除课程团队只改课程团队记录。
- 权限校验发生在计划写入之前。计划保存与团队同步使用同一事务，同步故障不吞掉，整笔回滚。团队名单鉴权与写入使用同一课程锁，锁后读当前有效名单，避免并发时读到旧权限。

## 教法、学法

保持原字符串字段，支持多值规范化。显式空串或 null 清空选项；未提交某字段则保留该字段已有值。更新 SQL 现在区分这两种情况，不再跳过清空动作。教学内容、教学环节、学时等字段保持原存储逻辑。

## 数据库与验证

本轮只读核对了可用测试库 `doinner-curriculum-test-3.2`：`author_ids` 为 varchar(500)、`teacher_id` 为 varchar(100)，团队表尚未创建、教法列仍为 varchar(255)。配置文件默认数据库 `my-curr` 在当前服务上不存在，本轮未修改配置。

已更新 `sql/20261014_course_team_member_ddl.sql`：仅创建新的团队表，人员帐号列为 varchar(100)，按课程与帐号唯一；已有教法/学法列使用增量 ALTER 放宽至 500。课程执笔人和计划成员无需结构变更。未执行数据库 DDL 或修改真实业务数据。

若某环境已执行此前团队表的数字 ID 版本，需要先核对该环境已有表与人员记录，再进行帐号迁移，不能将旧系统主键原样当帐号使用。本次已检查的测试库不存在这类表或数据。

本轮帐号、权限、同步及多选相关回归：44 个用例通过。覆盖不同数字 ID 的相同帐号、未注册帐号、帐号精确匹配、无权提权、团队身份独立、新建默认人员、跨计划资料隔离、旧单条接口去重、编辑不重新入队、更换人员同步、故障回滚、并发重复添加、真实 MyBatis 清空多选和未提交字段保持原值。

`TeachingPlanCreateWordTest` 另行运行：26 个用例，21 失败、1 异常，均因测试未设置登录上下文而收到 401。这与原实施说明中记录的既有失败数量和原因一致；本轮没有修改该测试类。当前结果不能证明 Word 导入、导出、打印的完整联调已通过。

配套 Postman：`doc/20261014_V4_统一认证帐号.postman_collection.json`。导入后设置实际 `baseUrl`、登录认证、课程/计划/成员记录 ID，再执行；示例 `teacher.a`、`教员甲` 都是占位人员。
